La historia

Un programa para registrar jugadores

Estamos creando un pequeño programa para registrar jugadores de fútbol. De cada jugador queremos guardar su nombre y la cantidad de goles. Además, cuando marque un gol, queremos que el propio objeto pueda actualizar ese dato.

La clase inicial

public class Jugador {

    String nombre;
    int goles;

    public void marcarGol() {
        goles++;
    }
}
nombre → dato del jugadorgoles → dato que puede cambiarmarcarGol() → acción que modifica goles

Paso 1 · Creamos un jugador

Conocemos a jugador1

Jugador jugador1 = new Jugador();

jugador1.nombre = "Lucía";
jugador1.goles = 0;

Hasta este momento, jugador1 representa a Lucía y tiene 0 goles.

Lucía → goles = 0

Paso 2 · El jugador marca un gol

El objeto cambia su propio estado

jugador1.marcarGol();

public void marcarGol() { goles++; }

¿Qué pasó?

Después de ejecutar marcarGol(), ¿cuánto vale jugador1.goles?

Hasta aquí todo parece funcionar bien. Cuando Lucía marca un gol usamos marcarGol() y el propio objeto actualiza sus goles. Pero mirá lo que también podemos hacer desde fuera del objeto.

jugador1.goles = -300;

Seguimos trabajando con el mismo objeto: jugador1.

Una pregunta sobre el modelo

¿Tiene sentido que Lucía pase a tener -300 goles?

jugador1.marcarGol();

El objeto controla cómo cambia goles.

jugador1.goles = -300;

Otra parte del programa coloca directamente cualquier valor.

Entonces, ¿para qué controlamos los goles mediante marcarGol() si alguien puede cambiar goles directamente?

Tenemos un problema

Una regla para cuidar los datos

Queremos que el objeto pueda controlar correctamente sus datos, pero actualmente cualquier parte del programa puede modificar goles directamente.
