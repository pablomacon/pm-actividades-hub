1. El problema de tener todo junto

Hasta ahora muchos programas estaban en un solo archivo, casi siempre en Main.java. Al crecer, allí se mezclan datos, cálculos, mensajes, condiciones, validaciones y resultados. Esto vuelve el programa difícil de leer, corregir y ampliar.

En una agencia de viajes podríamos guardar los datos de clientes, viajes, reservas y precios. La POO propone una forma de ordenar esa información.

2. Objetos y abstracción

Un objeto representa una parte simplificada del problema: una persona, un vehículo, una reserva o un jugador. No copiamos toda la realidad: elegimos los aspectos que sirven para el programa. Ese recorte se llama abstracción.

La misma persona necesita datos distintos en una agencia de viajes, un club deportivo, un sistema médico o un juego de fútbol.

3. Clase y objeto

Una clase es un molde que define las características y los comportamientos de objetos del mismo tipo. Cliente es una clase; cliente1 y cliente2 son objetos concretos que pueden tener datos diferentes.

public class Cliente {
  private String nombre;
  private String documento;
  private int edad;
  private String nacionalidad;
}

4. Atributos y métodos

Los atributos son las características que decidimos guardar. Los métodos representan los comportamientos que el objeto necesita realizar dentro del programa.

public void abonarViaje() {
  System.out.println("El viaje fue abonado");
}

La pregunta es: ¿qué necesito saber de este objeto y qué necesito que pueda hacer para resolver este problema?

5. Encapsulamiento

Encapsular es proteger los datos y controlar cómo se accede a ellos. Los atributos se declaran con private; luego se usan métodos como getNombre() y setNombre() para consultar o cambiar valores de forma controlada.

Usar POO ayuda a ordenar el código, separar responsabilidades, reutilizar clases y ampliar un programa sin destruir lo que ya funciona.
